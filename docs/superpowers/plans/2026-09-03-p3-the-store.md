# P3 — The Store: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give pgops a durable store — schema, migrations at boot, an in-process capture scheduler, delta maths and retention — so that history exists (#15, #21, #42) and the hygiene run model P2 depends on has somewhere to cache.

**Architecture:** The store is the price of pgops's refusal to call `pg_stat_statements_reset()`: cumulative counters are snapshotted and diffed at read time. `packages/checks` gains `src/store/` (schema, migrations, read/write), `src/series/` (the over-time half) and `src/capture.ts` (`captureOnce(ctx)` — no timer, no process assumptions). `apps/web/instrumentation.ts` owns the *timer only*, so lifting capture into a CLI later is a wrapper rather than a refactor. All of it is gated on an explicit `PGOPS_STORE_URL`: with none set, pgops issues no DDL anywhere and history reports `missing-store`.

**Tech Stack:** TypeScript 5.7, `pg` 8 (the only dependency `packages/checks` has, and that does not change), Next 16 App Router with the stable `instrumentation.ts` hook, React 19 Server Components, Vitest 4 (`unit` / `integration` / `web` projects), Testcontainers.

**Spec:** `docs/superpowers/specs/2026-09-03-pgops-full-parity-design.md` — §1.1 (`verdict: null`), §2 (the `class` collapse), §3 (the store and the DDL boundary), §5.1 (P3's one visible deliverable), §5.2 (registry variants), §10.2 (guards). The spec is the binding authority; this plan argues from it.

**Parent spec:** `docs/superpowers/specs/2026-08-26-pgops-web-design.md` §4 (series, schema, capture, delta maths, retention), as amended by §11 of the spec above.

**Prior art in this repo, both binding:**
- `docs/superpowers/reviews/2026-08-27-p0-decision-record.md` — rulings behind `packages/checks`.
- `docs/superpowers/reviews/2026-08-27-p1a-decision-record.md` — rulings behind `apps/web`.

## Global Constraints

- **Node floor 22. PostgreSQL floor 14.** CI matrix is 14, 16, 17, 18. Any SQL added here must run unchanged across all four, or branch on `ctx.serverVersion` explicitly. `pg_stat_statements_info` exists from PG14, so it needs no branch.
- **`packages/checks` dependencies stay exactly `["pg"]`.** Any change to that list is a finding to report, not a task to do. No migration framework, no cron library, no SQL file loader.
- **`packages/` uses `.js` import specifiers; `apps/web` does NOT.** `apps/web`'s tsconfig sets `moduleResolution: "bundler"`, under which Next's resolver will not map `./x.js` onto a sibling `x.tsx`.
- **`null` means "we could not look" and is never collapsed into a value.** Use `??`, never `||`, when defaulting a field that can legitimately be `false` or `0`.
- **Every rendering path calls `await connection()` from `next/server` before reading configuration.** `runCheckFor` already does this; anything new on a render path goes through the same seam.
- **Thresholds are data with a non-empty `because`.** No new threshold is introduced in this plan.
- **Migrations are TypeScript modules exporting SQL strings, never `.sql` files.** `packages/checks` builds with plain `tsc`, which copies no non-TS assets: a `.sql` file would be absent from `dist/` and the store would fail to migrate in the built image, with nothing catching it before runtime.
- **DDL appears only under `packages/checks/src/store/migrations/`.** Enforced by a guard in Task 11.
- **pgops issues no DDL against a monitored database, ever.** DDL is reachable only from the migration runner, which runs only when `PGOPS_STORE_URL` is set, and only against that URL.
- 2-space indent, ESM. Comments explain *why*, and cite the defect they prevent.

## Ruling 1: `check_results` is not in this phase

Spec §3.4 lists `pgops.check_results` in the schema, and spec §5 assigns it to
P2 ("`check_results`, 25 checks, six routes, grouped nav, badges"). Both are
right: §3.4 describes the store's full shape, §5 says when each table arrives.

Resolved here: **P3 ships migration `001` — `schema_version`, `databases`,
`queries`, `query_stats`, `space_stats`. P2 ships migration `002` —
`check_results`.** Migrations are forward-only and numbered, so this costs
nothing and avoids creating a table with no reader, which is the speculative
kind of work the project's own style rule rejects.

The same applies to the scheduler: P3 registers the **5-minute capture tick
only**. Spec §3.2's 15-minute hygiene tick has no hygiene checks to run until
P2 and is added there.

Two further spec sections have no subject in this phase and are therefore not
implemented here, listed so their absence reads as a decision rather than an
oversight:

- **§2.1 (hygiene degrading to `on-demand` with no store)** — P3 ships no
  hygiene check. The gate it degrades on (`storeUrl` returning null) IS built
  here, in Task 3; the degradation itself lands with the checks it governs.
- **§10.2 guard 2 (no hygiene or on-demand check reachable from a polled
  page)** — same reason, and see Ruling 4.

## Ruling 2: captured query text is redacted

Spec §7.3 of the parent spec says `redactSecrets` runs on every *rendered*
query. It is silent on captured text, because until this phase pgops stored
nothing.

`pgops.queries` is **durable storage**. A connection string or password
embedded in a query literal, written there, outlives every screenshot and every
page view — it is the exact hazard `redactSecrets` exists for, in its most
persistent form. So `captureOnce` redacts before it inserts, and the store
never holds the raw text. Task 6 asserts this.

## Ruling 3: two new `ParityEntry` variants, not a free-text escape hatch

#15 is a **series**: `Series<Point>` has `read`, not `sql`/`map`/`verdict`, so
`check: CheckId` cannot name it. #21 and #42 are **jobs**: the capture half of
"capture + retention" per the registry's own folds, run by the scheduler, and
neither a check nor an action.

`platform: string` would accept both, and that is exactly why it must not be
used: it is free text, so it cannot enforce "never names something that does
not exist" — the property that makes this registry worth having. Precedent is
`action: ActionId`, keyed off a real `ACTIONS` record. P3 follows it with
`series: SeriesId` (keyed off `SERIES`) and `job: JobId` (keyed off `JOBS`).

## Ruling 4: no vacuous guards

Spec §10.2 lists a guard requiring every `hygiene` and `on-demand` check to
declare a `timeoutMs`. **P3 ships no hygiene or `on-demand` check**, so that
guard would pass over an empty set and could never fail — the same defect
recorded in this project's own history, where a width assertion could not fail
because its subject was inside a box of that width.

It is therefore **deferred to P2**, where it has subjects. `timeoutMs` itself
is still implemented here (Task 2) and tested against a synthetic check that
actually sleeps, which can fail.

## Ruling 5: the integration split is P2's, and here is why not here

Spec §10.1 splits the integration suite into a serial `integration` project and
a parallel `integration-hygiene` one. This plan does **not** do it.

P3 adds four integration files to a suite already at ~244 s. That is a real
cost and the temptation to split now is genuine. Two hazards say otherwise, and
neither has an obvious answer:

1. **`globalSetup` is per-project.** Two projects declaring the same
   `global-setup.ts` start **two containers** per run, times the four-version
   matrix. The split would have to solve container sharing across projects
   first, and that is a design question, not a config line.
2. **Projects interleave inside one `vitest run`.** A parallel hygiene project
   running `pg_sleep(3)` (Task 2's timeout fixture) while the serial project
   asserts on `pg_stat_activity` reproduces exactly the flake
   `fileParallelism: false` exists to prevent — one layer up, where the
   existing comment does not warn about it.

Splitting properly is worth a task; splitting badly reintroduces the flake the
current config was written to kill. P2 brings 25 hygiene checks — the volume
that makes the split pay for itself — and it should be designed there, against
both hazards above, rather than tacked onto a phase that adds four files.

**The cost this defers, stated so it is not a surprise:** P3 leaves the
integration suite roughly 15–20 % slower per matrix entry.

And add, above `runCheck`:

```ts
/**
 * Run one query under a `statement_timeout`.
 *
 * `SET LOCAL` inside an explicit transaction, on a checked-out client — NOT
 * a bare `SET`. A bare `SET` is connection-scoped and survives the client's
 * return to the pool, so one hygiene check would silently arm a 10-second
 * timeout on whichever incident check drew that connection next, and the
 * failure would look like the database being slow rather than like pgops
 * misconfiguring it. `SET LOCAL` is discarded by COMMIT/ROLLBACK.
 *
 * The value is interpolated rather than bound because `SET LOCAL` does not
 * accept a bind parameter. `Math.trunc` plus a non-finite guard is what keeps
 * that safe: the result is provably an integer literal.
 */
async function queryWithTimeout(
  ctx: CheckContext,
  text: string,
  values: never[],
  timeoutMs: number,
): Promise<{ rows: unknown[] }> {
  if (!Number.isFinite(timeoutMs) || timeoutMs <= 0) {
    throw new Error(`timeoutMs must be a positive finite number, got ${timeoutMs}`);
  }
  const ms = Math.trunc(timeoutMs);
  const client = await ctx.target.connect();
  try {
    await client.query('BEGIN');
    await client.query(`SET LOCAL statement_timeout = ${ms}`);
    const result = await client.query(text, values);
    await client.query('COMMIT');
    return result;
  } catch (err) {
    // Best-effort: the transaction may already be aborted, in which case
    // ROLLBACK is what returns the connection to a usable state. Swallowing a
    // rollback failure here is correct — the original error is the one the
    // operator needs, and `release(err)` below destroys the connection anyway.
    await client.query('ROLLBACK').catch(() => {});
    throw err;
  } finally {
    client.release();
  }
}
```

 * configured. On the documented simplest deployment — `docker run -e
 * DATABASE_URL=…` — that would have pgops issue CREATE SCHEMA against a
 * production database an operator pointed it at expecting a read-only tool,
 * contradicting the README's "pgops does not install extensions, manage roles,
 * or run DDL". Cut. See spec 2026-09-03 §3.3.
 */
export function storeUrl(env: Record<string, string | undefined>): string | null {
  const url = env.PGOPS_STORE_URL;
  // `|| null` would be wrong for a legitimately falsy value; there is none
  // here, but the `?? ''` + explicit emptiness test keeps the rule visible.
  return (url ?? '') === '' ? null : url!;
}

// Module-level, for the same reason lib/pools.ts keeps POOLS: a pool per
// request would exhaust the store's connections. One store, so one entry.
let STORE: Pool | null = null;
let STORE_FOR: string | null = null;

export function storePool(env: Record<string, string | undefined>): Pool | null {
  const url = storeUrl(env);
  if (url === null) return null;
  if (STORE && STORE_FOR === url) return STORE;
  const pool = new Pool({ connectionString: url, max: 5, connectionTimeoutMillis: 5_000 });
  // Same reasoning as poolFor: an unhandled pool 'error' event terminates the
  // process, and a console that dies because the store blinked is worse than
  // one that reports history as unavailable.
  pool.on('error', () => {});
  STORE = pool;
  STORE_FOR = url;
  return pool;
}

```ts
import type { Pool } from 'pg';

/**
 * A fixed key for the migration lock. Arbitrary, but it must never change:
 * two pgops versions racing to migrate the same store have to contend on the
 * same key or the lock does nothing.
 */
export const MIGRATION_LOCK_KEY = 4021975;

/**
 * Namespace for per-database capture locks, used with the two-int form
 * `pg_try_advisory_lock(ns, database_id)` so a capture lock can never collide
 * with the single-int migration lock above.
 */
export const CAPTURE_LOCK_NS = 4021976;

/**
 * Run `fn` holding a session-level advisory lock, on one dedicated client.
 *
 * The lock must be taken and released on the SAME connection — advisory locks
 * are session-scoped — which is why this checks a client out rather than
 * querying the pool. `finally` releases it even when `fn` throws; without
 * that, one failed migration would block every replica from ever migrating
 * again until the process died.
 */
export async function withAdvisoryLock<T>(
  pool: Pool,
  key: number,
  fn: (client: import('pg').PoolClient) => Promise<T> | T,
): Promise<T> {
  const client = await pool.connect();
  try {
    await client.query('SELECT pg_advisory_lock($1)', [key]);
    try {
      return await fn(client);
    } finally {
      await client.query('SELECT pg_advisory_unlock($1)', [key]).catch(() => {});
    }
  } finally {
    client.release();
  }
}

/**
 * Try to take a per-database capture lock. Returns false immediately when
 * another replica holds it, rather than waiting.
 *
 * Waiting would be wrong: a tick that queues behind another replica's tick
 * runs a capture nobody needs, against a database pgops is meant to leave
 * alone. Skipping is the same rule usePoll applies to the browser — a tick
 * that lands while one is in flight is skipped, not queued.
 */
export async function tryCaptureLock(
  client: import('pg').PoolClient,
  databaseId: number,
): Promise<boolean> {
  const { rows } = await client.query<{ locked: boolean }>(
    'SELECT pg_try_advisory_lock($1, $2) AS locked',
    [CAPTURE_LOCK_NS, databaseId],
  );
  return rows[0]!.locked;
}

export async function releaseCaptureLock(
  client: import('pg').PoolClient,
  databaseId: number,
): Promise<void> {
  await client
    .query('SELECT pg_advisory_unlock($1, $2)', [CAPTURE_LOCK_NS, databaseId])
    .catch(() => {});
}
```

 * Migration 001 — the initial pgops schema.
 *
 * A TypeScript module exporting a string, NOT a .sql file. `packages/checks`
 * builds with plain `tsc`, which copies no non-TS assets: a .sql file would
 * simply be absent from dist/, and the store would fail to migrate in the
 * built image with nothing catching it before runtime.
 *
 * This directory is the ONLY place in the product permitted to contain DDL,
 * asserted by a guard in apps/web/test/guards.test.ts.
 */
export const SQL = `
CREATE SCHEMA IF NOT EXISTS pgops;

CREATE TABLE IF NOT EXISTS pgops.schema_version (
  version int NOT NULL,
  -- One row, enforced. A second row would make "what version is this store"
  -- ambiguous, and the runner reads it with a bare SELECT.
  singleton bool NOT NULL DEFAULT true UNIQUE CHECK (singleton)
);

CREATE TABLE IF NOT EXISTS pgops.databases (
  id         serial PRIMARY KEY,
  name       text NOT NULL UNIQUE,
  created_at timestamptz NOT NULL DEFAULT now()
);

-- Query text is stored ONCE per shape, not once per capture. A 5,000-shape
-- database capturing every 5 minutes would otherwise write roughly
-- 1 kB x 5,000 x 288/day of duplicated text. pgHero normalises the same way.
CREATE TABLE IF NOT EXISTS pgops.queries (
  id          serial PRIMARY KEY,
  database_id int NOT NULL REFERENCES pgops.databases(id) ON DELETE CASCADE,
  -- bigint: pg_stat_statements' 64-bit hash. Identity only, never arithmetic.
  queryid     bigint NOT NULL,
  -- Redacted before insert (redactSecrets). The store is durable; a secret in
  -- a query literal written here outlives every screenshot.
  query       text NOT NULL,
  first_seen  timestamptz NOT NULL DEFAULT now(),
  last_seen   timestamptz NOT NULL DEFAULT now(),
  UNIQUE (database_id, queryid)
);

-- CUMULATIVE counters, never deltas. pgops does not reset pg_stat_statements
-- (doing so silently breaks every other consumer on the database), so deltas
-- are computed at read time from consecutive snapshots. See series/query-stats.
CREATE TABLE IF NOT EXISTS pgops.query_stats (
  database_id      int NOT NULL REFERENCES pgops.databases(id) ON DELETE CASCADE,
  query_id         int NOT NULL REFERENCES pgops.queries(id) ON DELETE CASCADE,
  captured_at      timestamptz NOT NULL,
  calls            bigint NOT NULL,
  total_exec_time  double precision NOT NULL,
  rows             bigint NOT NULL,
  shared_blks_hit  bigint NOT NULL,
  shared_blks_read bigint NOT NULL,
  -- From pg_stat_statements_info (PG14+). An advance here marks a
  -- discontinuity: the interval spanning it is dropped, never charted.
  stats_reset      timestamptz,
  PRIMARY KEY (database_id, query_id, captured_at)
);

CREATE INDEX IF NOT EXISTS query_stats_captured_at_idx
  ON pgops.query_stats (database_id, captured_at DESC);

CREATE TABLE IF NOT EXISTS pgops.space_stats (
  database_id int NOT NULL REFERENCES pgops.databases(id) ON DELETE CASCADE,
  relation    text NOT NULL,
  captured_at timestamptz NOT NULL,
  size_bytes  bigint NOT NULL,
  PRIMARY KEY (database_id, relation, captured_at)
);

CREATE INDEX IF NOT EXISTS space_stats_captured_at_idx
  ON pgops.space_stats (database_id, captured_at DESC);

```ts
import type { Pool } from 'pg';
import { MIGRATION_LOCK_KEY, withAdvisoryLock } from './lock.js';
import { SQL as M001 } from './migrations/001-initial.js';

/**
 * Forward-only, numbered, idempotent. No migration framework — the list is
 * the framework, and `packages/checks` keeps exactly one dependency.
 *
 * Every entry must be safe to run against a store already at that version:
 * `register()` fires on every dev-server restart, so re-running is the normal
 * case rather than the exceptional one.
 */
const MIGRATIONS: readonly string[] = [M001];

/** The version this build knows how to produce. */
export const CURRENT_VERSION = MIGRATIONS.length;

/**
 * Bring `store` to CURRENT_VERSION and return the version now in force.
 *
 * Held under a session advisory lock so N replicas booting together migrate
 * once. Each migration and its version bump are ONE transaction: a migration
 * that half-applied and still recorded its version would leave a store that
 * reports healthy and is not.
 */
export async function migrate(store: Pool): Promise<number> {
  return withAdvisoryLock(store, MIGRATION_LOCK_KEY, async (client) => {
    // Bootstrap: the version table lives inside migration 001, so the very
    // first run has nowhere to read a version from. `to_regclass` answers
    // without throwing, unlike a SELECT against a missing relation.
    const { rows: probe } = await client.query<{ present: string | null }>(
      `SELECT to_regclass('pgops.schema_version')::text AS present`,
    );
    let current = 0;
    if (probe[0]!.present !== null) {
      const { rows } = await client.query<{ version: number }>(
        'SELECT version FROM pgops.schema_version',
      );
      current = rows[0]?.version ?? 0;
    }

    for (let v = current; v < MIGRATIONS.length; v += 1) {
      await client.query('BEGIN');
      try {
        await client.query(MIGRATIONS[v]!);
        await client.query(
          `INSERT INTO pgops.schema_version (version) VALUES ($1)
             ON CONFLICT (singleton) DO UPDATE SET version = EXCLUDED.version`,
          [v + 1],
        );
        await client.query('COMMIT');
      } catch (err) {
        await client.query('ROLLBACK').catch(() => {});
        throw err;
      }
    }
    return MIGRATIONS.length;
  });
}
```

import type { PoolClient } from 'pg';

export interface Retention { queryStatsDays: number; spaceStatsDays: number }

/**
 * pgHero's own defaults. Query stats are dense and short-lived interest;
 * space grows slowly and the interesting window is a quarter.
 */
export const RETENTION: Retention = { queryStatsDays: 14, spaceStatsDays: 90 };

export interface QueryStatsSnapshot {
  databaseId: number;
  queryId: number;
  capturedAt: Date;
  calls: number;
  totalExecTime: number;
  rows: number;
  sharedBlksHit: number;
  sharedBlksRead: number;
  statsReset: Date | null;
}

export interface SpaceSnapshot {
  databaseId: number;
  relation: string;
  capturedAt: Date;
  sizeBytes: number;
}

export async function upsertDatabase(client: PoolClient, name: string): Promise<number> {
  const { rows } = await client.query<{ id: number }>(
    `INSERT INTO pgops.databases (name) VALUES ($1)
       ON CONFLICT (name) DO UPDATE SET name = EXCLUDED.name
       RETURNING id`,
    [name],
  );
  return rows[0]!.id;
}

/**
 * `queryid` is passed and bound as TEXT, then cast in SQL.
 *
 * It is a 64-bit hash, and JavaScript's number cannot hold every 64-bit value
 * exactly — this is the same rule query-stats.ts already follows for its own
 * `queryid` field. Identity only; never arithmetic.
 */
export async function upsertQuery(
  client: PoolClient,
  databaseId: number,
  queryid: string,
  query: string,
): Promise<number> {
  const { rows } = await client.query<{ id: number }>(
    `INSERT INTO pgops.queries (database_id, queryid, query)
          VALUES ($1, $2::bigint, $3)
       ON CONFLICT (database_id, queryid)
       DO UPDATE SET last_seen = now(), query = EXCLUDED.query
       RETURNING id`,
    [databaseId, queryid, query],
  );
  return rows[0]!.id;
}

/**
 * One multi-row INSERT rather than one per shape: a 5,000-shape database
 * would otherwise issue 5,000 round trips every five minutes against a
 * database pgops is supposed to be leaving alone.
 *
 * ON CONFLICT DO NOTHING because the primary key is (database_id, query_id,
 * captured_at) and a retried tick must not fail on a snapshot already stored.
 */
export async function insertQueryStats(
  client: PoolClient,
  snapshots: QueryStatsSnapshot[],
): Promise<void> {
  if (snapshots.length === 0) return;
  const values: unknown[] = [];
  const tuples = snapshots.map((s, i) => {
    const b = i * 9;
    values.push(s.databaseId, s.queryId, s.capturedAt, s.calls, s.totalExecTime,
      s.rows, s.sharedBlksHit, s.sharedBlksRead, s.statsReset);
    return `($${b + 1}, $${b + 2}, $${b + 3}, $${b + 4}, $${b + 5}, $${b + 6}, $${b + 7}, $${b + 8}, $${b + 9})`;
  });
  await client.query(
    `INSERT INTO pgops.query_stats
       (database_id, query_id, captured_at, calls, total_exec_time, rows,
        shared_blks_hit, shared_blks_read, stats_reset)
     VALUES ${tuples.join(', ')}
     ON CONFLICT DO NOTHING`,
    values,
  );
}

export async function insertSpaceStats(
  client: PoolClient,
  snapshots: SpaceSnapshot[],
): Promise<void> {
  if (snapshots.length === 0) return;
  const values: unknown[] = [];
  const tuples = snapshots.map((s, i) => {
    const b = i * 4;
    values.push(s.databaseId, s.relation, s.capturedAt, s.sizeBytes);
    return `($${b + 1}, $${b + 2}, $${b + 3}, $${b + 4})`;
  });
  await client.query(
    `INSERT INTO pgops.space_stats (database_id, relation, captured_at, size_bytes)
     VALUES ${tuples.join(', ')}
     ON CONFLICT DO NOTHING`,
    values,
  );
}

/**
 * Pruning is called by `captureOnce` inside the SAME transaction as the
 * inserts, so retention cannot drift from capture — a separate schedule is a
 * second thing to get wrong, and the failure mode (a store that grows without
 * bound) is silent until the disk fills.
 */
export async function prune(
  client: PoolClient,
  databaseId: number,
  retention: Retention,
): Promise<void> {
  await client.query(
    `DELETE FROM pgops.query_stats
       WHERE database_id = $1 AND captured_at < now() - ($2 || ' days')::interval`,
    [databaseId, String(retention.queryStatsDays)],
  );
  await client.query(
    `DELETE FROM pgops.space_stats
       WHERE database_id = $1 AND captured_at < now() - ($2 || ' days')::interval`,
    [databaseId, String(retention.spaceStatsDays)],
  );
}

import { redactSecrets } from './redact.js';
import { releaseCaptureLock, tryCaptureLock } from './store/lock.js';
import {
  RETENTION, insertQueryStats, insertSpaceStats, prune, upsertDatabase, upsertQuery,
  type QueryStatsSnapshot, type Retention, type SpaceSnapshot,
} from './store/write.js';
import type { CheckContext, FailureReason } from './types.js';

export type CaptureOutcome =
  | { ok: true; shapes: number; relations: number }
  | { ok: false; reason: FailureReason; message: string }
  | { ok: 'skipped'; reason: 'locked' };

/**
 * Every top-level shape, unbounded — NOT the top-N the queries page reads.
 *
 * A capture that stored only the worst 100 shapes would make every trend for
 * a shape that drifted in and out of that window a series of holes, and the
 * holes would look like the query going quiet rather than like pgops not
 * having looked.
 *
 * `toplevel` is filtered where the column exists (PG14+ always, since that is
 * this project's floor). `stats_reset` comes from pg_stat_statements_info,
 * also PG14+, and is what makes a discontinuity detectable at read time.
 */
const QUERY_STATS_SQL = `
SELECT s.queryid::text        AS queryid,
       s.query                AS query,
       s.calls::text          AS calls,
       s.total_exec_time      AS total_exec_time,
       s.rows::text           AS rows,
       s.shared_blks_hit::text  AS shared_blks_hit,
       s.shared_blks_read::text AS shared_blks_read,
       i.stats_reset          AS stats_reset
  FROM pg_stat_statements s
  CROSS JOIN pg_stat_statements_info i
 WHERE s.toplevel
   AND s.queryid IS NOT NULL
`;

/**
 * Relation sizes for the space series. `pg_total_relation_size` includes
 * indexes and TOAST, which is the number an operator watching disk cares
 * about — the table's heap alone understates growth on any indexed table.
 */
const SPACE_SQL = `
SELECT (n.nspname || '.' || c.relname)             AS relation,
       pg_total_relation_size(c.oid)::text          AS size_bytes
  FROM pg_class c
  JOIN pg_namespace n ON n.oid = c.relnamespace
 WHERE c.relkind IN ('r', 'm', 'p')
   AND n.nspname NOT IN ('pg_catalog', 'information_schema', 'pgops')
`;

/**
 * One capture pass for one database. No timer, no process assumptions — the
 * scheduler that calls this lives in apps/web, so lifting capture into a CLI
 * later is a wrapper rather than a refactor.
 *
 * NEVER throws, for the same reason runCheck never rejects: this runs on a
 * background timer, and an unhandled rejection there terminates the web
 * process. A console that dies because a store blinked is worse than one that
 * reports history as unavailable.
 */
export async function captureOnce(
  ctx: CheckContext,
  name: string,
  retention: Retention = RETENTION,
): Promise<CaptureOutcome> {
  if (!ctx.store) {
    return {
      ok: false,
      reason: 'missing-store',
      message: 'No store configured; set PGOPS_STORE_URL to record history.',
    };
  }
  const store = ctx.store;
  let client;
  try {
    client = await store.connect();
  } catch (err) {
    return { ok: false, reason: 'unreachable', message: messageOf(err) };
  }

  let databaseId: number | null = null;
  try {
    databaseId = await upsertDatabase(client, name);
    if (!(await tryCaptureLock(client, databaseId))) {
      // Another replica is capturing this database. Skip, never queue — a
      // queued tick runs a capture nobody needs against a database pgops is
      // meant to be leaving alone.
      return { ok: 'skipped', reason: 'locked' };
    }

    const capturedAt = new Date();

    // pg_stat_statements may not be installed. That is not a capture failure
    // for the whole database — space stats are independent and still useful —
    // so it degrades to zero shapes rather than aborting.
    let queryRows: QueryRow[] = [];
    try {
      const r = await ctx.target.query<QueryRow>(QUERY_STATS_SQL);
      queryRows = r.rows;
    } catch {
      queryRows = [];
    }

    const spaceResult = await ctx.target.query<SpaceRow>(SPACE_SQL);

    await client.query('BEGIN');
    try {
      const stats: QueryStatsSnapshot[] = [];
      for (const row of queryRows) {
        // Redact BEFORE the insert. pgops.queries is durable storage: a
        // connection string or password in a query literal written there
        // outlives every screenshot and every page view. Ruling 2.
        const queryId = await upsertQuery(
          client, databaseId, row.queryid, redactSecrets(row.query ?? ''),
        );
        stats.push({
          databaseId, queryId, capturedAt,
          calls: Number(row.calls),
          totalExecTime: row.total_exec_time,
          rows: Number(row.rows),
          sharedBlksHit: Number(row.shared_blks_hit),
          sharedBlksRead: Number(row.shared_blks_read),
          statsReset: row.stats_reset,
        });
      }
      await insertQueryStats(client, stats);

      const space: SpaceSnapshot[] = spaceResult.rows.map((r) => ({
        databaseId: databaseId!, relation: r.relation,
        capturedAt, sizeBytes: Number(r.size_bytes),
      }));
      await insertSpaceStats(client, space);

      // Same transaction as the inserts: retention cannot drift from capture.
      await prune(client, databaseId, retention);
      await client.query('COMMIT');
      return { ok: true, shapes: stats.length, relations: space.length };
    } catch (err) {
      await client.query('ROLLBACK').catch(() => {});
      return { ok: false, reason: 'error', message: messageOf(err) };
    }
  } catch (err) {
    return { ok: false, reason: 'error', message: messageOf(err) };
  } finally {
    if (databaseId !== null) await releaseCaptureLock(client, databaseId);
    client.release();
  }
}

interface QueryRow {
  queryid: string; query: string | null; calls: string;
  total_exec_time: number; rows: string;
  shared_blks_hit: string; shared_blks_read: string;
  stats_reset: Date | null;
}
interface SpaceRow { relation: string; size_bytes: string }

function messageOf(err: unknown): string {
  return err instanceof Error ? err.message : String(err);
}

import type { CheckContext, FailureReason, Requirement } from '../types.js';

export interface TimeRange { from: Date; to: Date }

/**
 * A check answers "what is true now" and yields one verdict. A series answers
 * "how has this moved" and yields many points with NO verdict at all. They
 * share pools, requirements and the failure envelope, and share nothing else
 * — siblings, not variants. See the parent spec §4.1.
 */
export interface Series<Point, Opts = void> {
  id: string;
  title: string;
  read: (ctx: CheckContext, range: TimeRange, opts: Opts) => Promise<Point[]>;
  requires?: Requirement[];
}

export type SeriesResult<P> =
  | { ok: true; points: P[]; readAt: number }
  | { ok: false; reason: FailureReason; message: string; remedy?: string };

/**
 * Run one series. NEVER rejects — same contract and same reasoning as
 * runCheck: one unreadable series must never blank a page.
 *
 * The store check comes first and is its own reason. `missing-store` renders
 * as "set this environment variable"; reported as `error` it would read as
 * the database being unwell.
 */
export async function runSeries<P, Opts = void>(
  ctx: CheckContext,
  series: Series<P, Opts>,
  range: TimeRange,
  opts: Opts = undefined as Opts,
): Promise<SeriesResult<P>> {
  if (!ctx.store) {
    return {
      ok: false,
      reason: 'missing-store',
      message: `${series.id} needs the pgops store, which is not configured.`,
      remedy: 'Set PGOPS_STORE_URL to a Postgres database pgops may create its own schema in.',
    };
  }
  const version = series.requires?.find((r) => r.kind === 'version');
  if (version && ctx.serverVersion < version.min) {
    return {
      ok: false,
      reason: 'unsupported-version',
      message: `${series.id} requires server_version_num >= ${version.min}, found ${ctx.serverVersion}`,
    };
  }
  const readAt = Date.now();
  try {
    return { ok: true, points: await series.read(ctx, range, opts), readAt };
  } catch (err) {
    return { ok: false, reason: 'error', message: err instanceof Error ? err.message : String(err) };
  }
}

```ts
export interface CounterPoint {
  capturedAt: Date;
  calls: number;
  totalExecTime: number;
  rows: number;
  sharedBlksHit: number;
  sharedBlksRead: number;
  /** From pg_stat_statements_info. An advance marks a discontinuity. */
  statsReset: Date | null;
}

export interface Interval {
  from: Date;
  to: Date;
  calls: number;
  totalExecTime: number;
  rows: number;
  sharedBlksHit: number;
  sharedBlksRead: number;
}

/**
 * Difference consecutive cumulative snapshots into intervals.
 *
 * Counters are cumulative since the last reset, and there are two hazards,
 * both of which produce the same signature and get the same treatment:
 *
 *   - an explicit pg_stat_statements_reset(), visible as stats_reset advancing;
 *   - LRU eviction — pg_stat_statements.max defaults to 5000, and a shape
 *     evicted then re-added restarts from zero, which for that row is
 *     indistinguishable from a reset.
 *
 * An interval spanning either is a DISCONTINUITY and is DROPPED — not clamped
 * to zero, not rendered as a spike. A gap in a chart is honest; a spike is a
 * lie that reads as an incident, and this tool exists to be trusted during
 * one.
 *
 * Both conditions are tested, not just the counter one: after a reset the
 * counters can climb past their old values before the next capture, and
 * counter comparison alone would miss it and chart the whole post-reset total
 * as a five-minute spike.
 */
export function deltas(points: CounterPoint[]): Interval[] {
  const sorted = [...points].sort((a, b) => a.capturedAt.getTime() - b.capturedAt.getTime());
  const out: Interval[] = [];
  for (let i = 1; i < sorted.length; i += 1) {
    const prev = sorted[i - 1]!;
    const next = sorted[i]!;
    if (isDiscontinuity(prev, next)) continue;
    out.push({
      from: prev.capturedAt,
      to: next.capturedAt,
      calls: next.calls - prev.calls,
      totalExecTime: next.totalExecTime - prev.totalExecTime,
      rows: next.rows - prev.rows,
      sharedBlksHit: next.sharedBlksHit - prev.sharedBlksHit,
      sharedBlksRead: next.sharedBlksRead - prev.sharedBlksRead,
    });
  }
  return out;
}

function isDiscontinuity(prev: CounterPoint, next: CounterPoint): boolean {
  const resetAdvanced =
    next.statsReset !== null &&
    (prev.statsReset === null || next.statsReset.getTime() > prev.statsReset.getTime());
  if (resetAdvanced) return true;
  return next.calls < prev.calls
    || next.totalExecTime < prev.totalExecTime
    || next.rows < prev.rows
    || next.sharedBlksHit < prev.sharedBlksHit
    || next.sharedBlksRead < prev.sharedBlksRead;
}
```

import type { PoolClient, Pool } from 'pg';
import type { CounterPoint } from '../series/query-stats.js';

export interface StoredShape {
  queryid: string;
  query: string;
  points: CounterPoint[];
}

/**
 * Every stored snapshot for one database in one window, grouped by shape.
 *
 * Ordered by captured_at so `deltas` receives points in order; it sorts again
 * defensively, because a series that silently reversed would produce negative
 * intervals that read as discontinuities and vanish.
 */
export async function readQueryStats(
  store: Pool | PoolClient,
  databaseName: string,
  from: Date,
  to: Date,
): Promise<StoredShape[]> {
  const { rows } = await store.query<Row>(
    `SELECT q.queryid::text          AS queryid,
            q.query                  AS query,
            s.captured_at            AS captured_at,
            s.calls::text            AS calls,
            s.total_exec_time        AS total_exec_time,
            s.rows::text             AS rows,
            s.shared_blks_hit::text  AS shared_blks_hit,
            s.shared_blks_read::text AS shared_blks_read,
            s.stats_reset            AS stats_reset
       FROM pgops.query_stats s
       JOIN pgops.queries   q ON q.id = s.query_id
       JOIN pgops.databases d ON d.id = s.database_id
      WHERE d.name = $1 AND s.captured_at >= $2 AND s.captured_at <= $3
      ORDER BY q.queryid, s.captured_at`,
    [databaseName, from, to],
  );

  const byShape = new Map<string, StoredShape>();
  for (const r of rows) {
    let shape = byShape.get(r.queryid);
    if (!shape) {
      shape = { queryid: r.queryid, query: r.query, points: [] };
      byShape.set(r.queryid, shape);
    }
    shape.points.push({
      capturedAt: r.captured_at,
      calls: Number(r.calls),
      totalExecTime: r.total_exec_time,
      rows: Number(r.rows),
      sharedBlksHit: Number(r.shared_blks_hit),
      sharedBlksRead: Number(r.shared_blks_read),
      statsReset: r.stats_reset,
    });
  }
  return [...byShape.values()];
}

interface Row {
  queryid: string; query: string; captured_at: Date; calls: string;
  total_exec_time: number; rows: string;
  shared_blks_hit: string; shared_blks_read: string; stats_reset: Date | null;
}

Create `apps/web/lib/scheduler.ts`:

```ts
import type { Pool } from 'pg';

/**
 * pgHero's own capture cadence. Dense enough for query-stat deltas to chart,
 * sparse enough that space stats cost nothing.
 *
 * The 15-minute hygiene tick spec §3.2 describes is NOT here: P3 ships no
 * hygiene check, so a second timer would have nothing to run. It arrives with
 * P2, alongside the checks it serves.
 */
export const CAPTURE_INTERVAL_MS = 5 * 60_000;

export interface SchedulerDeps {
  store: Pool | null;
  names: () => string[];
  capture: (name: string) => Promise<unknown>;
  migrate: (store: Pool) => Promise<number>;
}

let timer: ReturnType<typeof setInterval> | null = null;
let running = false;

/**
 * Start the capture timer. Returns whether it started.
 *
 * Dependencies are passed in rather than imported so this is testable with no
 * database and no Next server — the same reason `packages/checks` takes pools
 * instead of reaching for them.
 */
export async function startScheduler(deps: SchedulerDeps): Promise<boolean> {
  // No store, no scheduler, and — the part that matters — no DDL. See
  // lib/store.ts on why there is no fallback to a monitored database.
  if (deps.store === null) return false;
  if (timer !== null) return true;

  await deps.migrate(deps.store);

  timer = setInterval(() => { void tick(deps); }, CAPTURE_INTERVAL_MS);
  // Do not hold the process open for the sake of the timer.
  timer.unref?.();
  return true;
}

export function stopScheduler(): void {
  if (timer !== null) clearInterval(timer);
  timer = null;
  running = false;
}

/**
 * One pass over every configured database, in series.
 *
 * SERIAL, not parallel: a diagnostic tool must not be the reason connections
 * run out, which is the same reasoning that caps `poolFor` at ten.
 *
 * SKIPPED, not queued, when the previous tick is still in flight — the rule
 * `usePoll` applies in the browser, for the same reason: the tool must never
 * add load to the database it is diagnosing.
 *
 * Every error is swallowed. This runs on a timer with no caller to reject to,
 * and an unhandled rejection in that position terminates the Node process —
 * a console that dies because the store blinked is worse than one that
 * reports history as unavailable.
 */
async function tick(deps: SchedulerDeps): Promise<void> {
  if (running) return;
  running = true;
  try {
    for (const name of deps.names()) {
      try {
        await deps.capture(name);
      } catch (err) {
        console.error('[pgops] capture failed for %s: %s', name, (err as Error)?.message ?? err);
      }
    }
  } finally {
    running = false;
  }
}
```

- [ ] **Step 4: Write the instrumentation hook**

Create `apps/web/instrumentation.ts`:

```ts
/**
 * Next calls `register()` once per server instance — and for the EDGE runtime
 * as well as the node one, where `pg` cannot run. The guard is not optional.
 *
 * It also fires on every dev-server restart, which is why `migrate` is
 * forward-only and idempotent: re-running is the normal case here, not the
 * exceptional one.
 *
 * The imports are dynamic and INSIDE the guard so that `pg` and the store
 * modules are never pulled into an edge bundle.
 */
export async function register(): Promise<void> {
  if (process.env.NEXT_RUNTIME !== 'nodejs') return;

  const [{ startScheduler }, { storePool }, { contextFor, databaseNames }, checks] =
    await Promise.all([
      import('./lib/scheduler'),
      import('./lib/store'),
      import('./lib/pools'),
      import('@pgops/checks'),
    ]);

  const store = storePool(process.env);
  if (store === null) {
    console.info('[pgops] PGOPS_STORE_URL is not set; history is disabled and no DDL will run.');
    return;
  }

  await startScheduler({
    store,
    names: () => {
      // Configuration is read per TICK, not once at boot: PGOPS_CONFIG_FILE
      // points at a mounted file that can change without the container
      // restarting, and the whole configuration model is "read at request
      // time, not build time".
      try {
        return databaseNames();
      } catch {
        return [];
      }
    },
    capture: async (name) => checks.captureOnce(await contextFor(name), name),
    migrate: checks.migrate,
  });
}
```

/**
 * Delta for each shape between the two most recent captures.
 *
 * Returns null — not an empty map — when there is no store, so the column can
 * be ABSENT rather than blank. A blank delta column reads as "this query has
 * not moved"; it would mean "we never looked".
 */
async function lastIntervalByQueryid(
  name: string,
): Promise<Map<string, { calls: number; totalExecTime: number }> | null> {
  const ctx = await contextFor(name);
  if (!ctx.store) return null;
  // Two captures at a five-minute cadence sit inside twenty minutes with room
  // for one missed tick.
  const result = await runSeries(
    ctx, SERIES.historicalQueryStats,
    { from: new Date(Date.now() - 20 * 60_000), to: new Date() },
    { databaseName: name },
  );
  if (!result.ok) return null;
  const out = new Map<string, { calls: number; totalExecTime: number }>();
  for (const shape of result.points) {
    const last = shape.intervals.at(-1);
    if (last) out.set(shape.queryid, { calls: last.calls, totalExecTime: last.totalExecTime });
  }
  return out;
}
