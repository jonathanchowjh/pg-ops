## Global Constraints

- `packages/checks` stays framework-free; its `dependencies` are exactly `["pg"]`.
- **Null discipline.** `null` means "we could not look". Never collapsed to 0. `??`, never `||`.
- **§2.2.** A series carries no verdict. Ever. `SeriesResult` has no verdict field and none is invented at the page.
- **§3.5.** An interval spanning a counter decrease or a `stats_reset` advance is DROPPED, never clamped. A gap is honest; a spike is a lie.
- **The DDL boundary.** `packages/checks/src` issues no DDL outside `store/migrations/`. `guards.test.ts` matches `/\b(?:(?:CREATE|ALTER|DROP)\s+(?:MATERIALIZED\s+)?(?:SCHEMA|TABLE|INDEX|VIEW|EXTENSION|SEQUENCE|FUNCTION|ROLE|USER|DATABASE)\b|TRUNCATE\s+…|GRANT\s+[A-Z]{2,}\b)/i` over **both** `packages/checks/src` and `apps/web`, comments stripped but **string literals not**. Prose that names a DDL statement trips it — reword.
- **The poll boundary.** `<Refresh>` renders in exactly the five `INCIDENT_PAGES` plus the overview. Every route added here is hygiene: **no `<Refresh>`**, and `guards.test.ts` fails if one appears.
- **§5.1.** A store read from an incident page is "one indexed lookup per render and it must stay that way." Every `read` added here takes bounds and the caller passes them.
- **Store reads are parameterised.** `$n` fragments built into a list, never interpolated values — `store/read.ts` and `store/write.ts` both already do this.
- **`bigint` arrives as a string** from node-postgres. `size_bytes` is `bigint`; cast or convert in the mapper, and type the row field as what actually arrives.
- Two typechecks, both must pass: `npm run typecheck:test` (packages) and `npm run --workspace @pgops/web typecheck` (resolves `@pgops/checks` through built `dist/` — rebuild before believing it).
- **Never run two of `test:web` / `test:int` / the web typecheck concurrently.** They race `rm -rf dist && tsc`. A moving pair of `apps/web` route failures is environmental, not a regression — re-run clean.

### Task 1: `readSpaceGrowth` — the store read behind #40

**Files:**
- Modify: `packages/checks/src/store/read.ts`
- Test: `packages/checks/test/store.int.test.ts`

**Interfaces:**
- Consumes: `pgops.space_stats (database_id, relation, captured_at, size_bytes)` — PK `(database_id, relation, captured_at)`, index on `(database_id, captured_at DESC)`.
- Produces: `readSpaceGrowth(store: Pool | PoolClient, databaseName: string, from: Date, to: Date): Promise<StoredGrowth[]>` where `interface StoredGrowth { relation: string; firstBytes: number; lastBytes: number; firstAt: Date; lastAt: Date; points: number }`.

**What pgHero does, and where we diverge.** `space_growth(days: 7)` takes the FIRST captured size in the window (`sizes[1]` of an ordered `array_agg`) and subtracts it from the relation's **current, live** size, measured by re-running `relation_sizes` against the monitored database. We use the **last captured** size instead, and the reason is the honesty rule: mixing a stored reading with a live one silently attributes five minutes of unrecorded change to a seven-day trend, and makes the number irreproducible — re-render the page and it moves. Both endpoints come from the store, and `lastAt` is rendered so the operator can see how fresh the window is.

**Traps:**
- **`DISTINCT ON` needs its own `ORDER BY`** inside the CTE, and `boundaries.test.ts`'s `::text`-alias guard bounds each `ORDER BY` clause at its own `LIMIT` or closing paren. Qualify sort keys with a table alias.
- **`size_bytes` is `bigint`.** It arrives as a string. Convert in the mapper, and type the row field `string`.
- **A relation with one capture has no growth.** `firstBytes === lastBytes` and `points === 1`. That is not zero growth; the page must distinguish them, so `points` is returned rather than inferred.
- **Do not `JOIN` the live database.** This reader touches the store only. `ctx.target` is not in scope here and must not be.

```typescript
async function withStore(fn: (client: import('pg').PoolClient) => Promise<void>): Promise<void> {
  await withPostgres(async (_ctx, pool) => {
    await migrate(pool);
    const client = await pool.connect();
    try {
      await fn(client);
    } finally {
      client.release();
    }
  });
}
```

```typescript
// packages/checks/src/store/read.ts
export interface StoredGrowth {
  relation: string;
  firstBytes: number;
  lastBytes: number;
  firstAt: Date;
  lastAt: Date;
  /** Captures in the window. 1 means there is no interval to measure. */
  points: number;
}

interface GrowthRow {
  relation: string;
  /** bigint -> string, per this package's convention. */
  first_bytes: string;
  last_bytes: string;
  first_at: Date;
  last_at: Date;
  points: string;
}

/**
 * #40, and the divergence from pgHero is deliberate.
 *
 * `space_growth` takes the first captured size in the window and subtracts it
 * from the relation's CURRENT, LIVE size — it re-runs `relation_sizes` against
 * the monitored database to get the second endpoint. That mixes a stored
 * reading with a live one: up to one capture interval of change is silently
 * attributed to the whole window, and the number moves every time the page is
 * re-rendered, so two operators looking at the same "7-day growth" see
 * different figures. Both endpoints here come from the store, and `lastAt`
 * travels with them so the surface can say how fresh the window is.
 *
 * One pass with `min`/`max` over `captured_at`, not two `DISTINCT ON`
 * subqueries: `(database_id, relation, captured_at)` is the primary key, so
 * this is an index scan per relation either way, and one aggregate is one
 * plan to read.
 */
export async function readSpaceGrowth(
  store: Pool | PoolClient,
  databaseName: string,
  from: Date,
  to: Date,
): Promise<StoredGrowth[]> {
  const { rows } = await store.query<GrowthRow>(`
    WITH bounds AS (
      SELECT s.relation,
             min(s.captured_at) AS first_at,
             max(s.captured_at) AS last_at,
             count(*)           AS points
        FROM pgops.space_stats s
        JOIN pgops.databases d ON d.id = s.database_id
       WHERE d.name = $1 AND s.captured_at >= $2 AND s.captured_at <= $3
       GROUP BY s.relation
    )
    SELECT b.relation,
           f.size_bytes::text AS first_bytes,
           l.size_bytes::text AS last_bytes,
           b.first_at,
           b.last_at,
           b.points::text     AS points
      FROM bounds b
      JOIN pgops.databases d ON d.name = $1
      JOIN pgops.space_stats f
        ON f.database_id = d.id AND f.relation = b.relation AND f.captured_at = b.first_at
      JOIN pgops.space_stats l
        ON l.database_id = d.id AND l.relation = b.relation AND l.captured_at = b.last_at
     ORDER BY (l.size_bytes - f.size_bytes) DESC, b.relation`,
    [databaseName, from, to]);

  return rows.map((r) => ({
    relation: r.relation,
    firstBytes: Number(r.first_bytes),
    lastBytes: Number(r.last_bytes),
    firstAt: r.first_at,
    lastAt: r.last_at,
    points: Number(r.points),
  }));
}
```

```typescript
// packages/checks/src/store/read.ts
export interface StoredSize { capturedAt: Date; sizeBytes: number }

interface SizeRow { captured_at: Date; size_bytes: string }

/**
 * #41. One relation's captured sizes, oldest first.
 *
 * `maxPoints` keeps the most RECENT N and then re-orders ascending, which is
 * why the subquery exists: thirty days at the five-minute capture cadence is
 * 8,640 rows for one relation (§5.1), and a chart truncated from the wrong end
 * would show the history and hide the present. `ORDER BY ... DESC LIMIT n`
 * inside, ascending outside.
 */
export async function readRelationSpace(
  store: Pool | PoolClient,
  databaseName: string,
  relation: string,
  from: Date,
  to: Date,
  opts: { maxPoints?: number } = {},
): Promise<StoredSize[]> {
  const values: unknown[] = [databaseName, relation, from, to];
  let bound = '';
  if (opts.maxPoints !== undefined) {
    values.push(opts.maxPoints);
    bound = `ORDER BY s.captured_at DESC LIMIT $${values.length}`;
  }
  const { rows } = await store.query<SizeRow>(`
    SELECT p.captured_at, p.size_bytes::text AS size_bytes
      FROM (
        SELECT s.captured_at, s.size_bytes
          FROM pgops.space_stats s
          JOIN pgops.databases d ON d.id = s.database_id
         WHERE d.name = $1 AND s.relation = $2
           AND s.captured_at >= $3 AND s.captured_at <= $4
         ${bound}
      ) p
     ORDER BY p.captured_at ASC`, values);

  return rows.map((r) => ({ capturedAt: r.captured_at, sizeBytes: Number(r.size_bytes) }));
}
```

```typescript
// packages/checks/src/series/space.ts
import { readRelationSpace, readSpaceGrowth, type StoredGrowth, type StoredSize } from '../store/read.js';
import type { Series } from '../types.js';

export interface GrowthPoint {
  relation: string;
  firstBytes: number;
  lastBytes: number;
  /** `lastBytes - firstBytes`. Negative is a real reading — see the docblock. */
  growthBytes: number;
  firstAt: Date;
  lastAt: Date;
  /** Captures in the window. 1 means there is no interval, not zero growth. */
  points: number;
}

/**
 * The one subtraction, in one place.
 *
 * `readSpaceGrowth` returns both endpoints rather than their difference so the
 * surface can show what the window actually contained — computing the
 * difference in SQL as well would be two expressions that drift.
 *
 * Negative is NOT clamped. A relation shrinks for ordinary reasons — VACUUM
 * FULL, a dropped index, a detached partition — and a space page that can only
 * count upward cannot show an operator that the thing they just did worked.
 */
export function toGrowthPoints(rows: StoredGrowth[]): GrowthPoint[] {
  return rows.map((r) => ({
    relation: r.relation,
    firstBytes: r.firstBytes,
    lastBytes: r.lastBytes,
```

```typescript
/**
```

```tsx
 * A sparkline, as an inline SVG polyline. No charting dependency: this is two
 * sparklines in the whole console, and `apps/web` is deliberately thin.
 *
 * `viewBox` with `preserveAspectRatio="none"` means the caller sizes it in
 * CSS and the geometry below is always 0..100 by 0..30 — so there is no
 * measurement, no ref, and nothing that behaves differently on the server.
 */
export function Spark({ points, label }: { points: readonly number[]; label: string }) {
  if (points.length === 0) return null;
  const min = Math.min(...points);
  const max = Math.max(...points);
  // A flat series has range 0, and (v - min) / 0 is NaN — an SVG with NaN
  // coordinates renders NOTHING, which would make the most ordinary case
  // (a relation that has not changed) look like a broken chart.
  const range = max - min || 1;
  const step = points.length === 1 ? 0 : 100 / (points.length - 1);
  const coords = points
    .map((v, i) => `${(i * step).toFixed(2)},${(30 - ((v - min) / range) * 28 - 1).toFixed(2)}`)
    .join(' ');

  return (
    <svg
      viewBox="0 0 100 30"
      preserveAspectRatio="none"
      role="img"
      aria-label={label}
      className="h-12 w-full text-foreground"
    >
      <polyline points={coords} fill="none" stroke="currentColor" strokeWidth="1" vectorEffect="non-scaling-stroke" />
    </svg>
  );
}
```
